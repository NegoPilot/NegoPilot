# frontend

구매 담당자가 기업과 법령을 질문하는 Vue 화면입니다. 기업을 미리 선택하지 않고 AI 대화에서 질문합니다. 화면은 Spring 공개 API만 호출합니다. 개발 서버는 `/api`와 `/health` 요청을 `NEGOPILOT_BACKEND_URL`로 전달합니다.

## 연결된 기능

| 기능 | 공개 API | 계약 |
| --- | --- | --- |
| 회원가입과 로그인 및 세션 확인 | `/api/v1/auth/signup` `login` `me` `logout` `csrf` | [회원과 세션](../docs/contracts/membership.md) |
| 개인 대화 생성과 목록 및 제목 변경과 삭제 | `/api/v2/conversations` 및 `/{id}` | [개인 대화 이력 v0.4](../docs/contracts/history.md) |
| 질문 전송과 이전 메시지 조회 | `/api/v2/conversations/{id}/messages` | [대화 이력](../docs/contracts/history.md)과 [Generation v0.3](../docs/contracts/agent-generation.md) |
| 저장된 답변과 근거 조회 | `/api/v2/conversations/{id}/responses/{responseId}` | [대화 이력](../docs/contracts/history.md) |

대화 목록과 스냅샷의 외부 계약은 `schema_version: "0.4"`와 `storage: "database"`입니다. 저장된 Generation 응답은 `schema_version: "0.3"`을 유지합니다. 프런트는 전체 응답과 원본 근거를 보존하고 표시할 때만 필드를 변환합니다.

### 로그인과 가입

회원가입은 이름과 이메일 및 비밀번호와 부서와 직책을 서버에 저장합니다. 이름과 이메일 및 비밀번호와 부서는 필수입니다. 비밀번호 확인은 화면 검사용이며 서버에 보내지 않습니다. 비밀번호는 영문과 숫자 및 특수문자를 포함한 8자 이상이어야 합니다. 최대 길이는 UTF-8 기준 72바이트입니다.

신규 회원은 `PENDING`으로 생성됩니다. 가입 후 로그인하면 승인 대기 화면에서 상태를 확인할 수 있습니다. `ACTIVE` 회원만 AI 대화를 이용합니다. 회원 승인은 현재 관리자 API로 처리하며 관리자 화면 연결은 준비 중입니다. 최초 관리자는 [관리자 생성 절차](../docs/contracts/membership.md#최초-관리자-생성)로 만듭니다.

인증은 서버의 HttpOnly 세션 쿠키를 사용합니다. 변경 요청에는 `/api/v1/auth/csrf`에서 받은 토큰을 보냅니다. 역할과 승인 상태는 서버가 반환한 회원 정보로 확인합니다. 예전 시안의 브라우저 저장 역할 값은 인증에 사용하지 않습니다. 임의의 이메일이나 비밀번호로 로그인할 수 없습니다.

### AI 대화와 개인 이력

- `/`와 로그인 후 기본 경로는 `/chat`입니다. 공급사 검색 API의 성공 여부와 관계없이 직접 질문할 수 있습니다.
- `live`에서는 Agent가 질문 해석과 필요한 도구 호출 및 답변 생성을 실행합니다. 이전 대화는 서버가 전달하므로 같은 대화에서 후속 질문을 할 수 있습니다.
- 대화 기록에서 이전 대화를 열고 계속 질문할 수 있습니다. 제목 변경과 영구 삭제 및 새 대화를 지원합니다. 목록은 20개씩 조회하고 메시지는 최근 50개부터 보여 줍니다. 이전 메시지는 더 불러올 수 있습니다.
- 대화와 전체 응답은 PostgreSQL에 저장됩니다. 서버 재시작 후에도 같은 계정으로 조회할 수 있습니다. 다른 회원의 대화는 관리자에게도 공개되지 않습니다.
- HTTP 200이어도 `execution_status: "FAILED"`이면 성공 메시지로 남기지 않습니다. 입력 질문을 복원하고 오류를 표시합니다. 같은 요청 재시도에는 `Idempotency-Key`를 재사용합니다.
- 대화를 전환하면 이전 화면의 요청을 취소하고 늦은 응답이 다른 대화에 표시되지 않게 합니다. 이미 시작된 서버 처리는 완료될 수 있으므로 기록 목록을 새로고침해 결과를 확인할 수 있습니다.
- 답변의 인용 번호와 근거 링크는 새 탭을 엽니다. 저장된 응답을 별도 API로 조회하므로 최근 50개보다 오래된 답변의 근거도 열 수 있습니다. 대화를 삭제하면 그 대화의 근거도 조회할 수 없습니다.

### 실행 모드와 데이터 출처

`live`는 실제 모델과 도구 실행을 뜻합니다. 조회된 모든 값이 실제 기업 데이터라는 뜻은 아닙니다. `stub`는 정해진 테스트 응답으로 통신을 확인하는 모드입니다. 실제 Agent 호출이 실패했다고 자동으로 stub 응답으로 바꾸지 않습니다.

근거 상세와 조회 요약은 출처를 구분해 표시합니다.

| 출처 | 표시 의미 |
| --- | --- |
| `DART` | DART 공시 |
| `MOCK` | 가상 데이터 |
| `MANUAL` | 관리자 입력 |
| `STUB` | 테스트 응답 |
| `MIXED` | 여러 출처가 섞인 자료 |
| `UNKNOWN` 또는 미제공 | 출처 정보 없음 |

기업 기본 정보의 `source`와 `profile_origin_source`를 구분합니다. 인증은 `certification_source`를 사용합니다. 생산능력은 `capability_source`를 사용합니다. 품질과 납기는 `quality_source`를 사용합니다. 재무는 각 재무 행의 출처를 사용합니다. 기본 정보가 DART라는 이유로 인증이나 품질 또는 견적을 DART로 표시하지 않습니다. 출처가 없는 견적과 계약은 출처 정보 없음으로 표시합니다.

business MCP의 flat 응답을 화면용 형식으로 변환합니다. `on_time_rate`의 0..1 비율은 0..100 백분율로 표시합니다. 이미 백분율인 `on_time_delivery_rate`는 그대로 사용합니다. 재무 금액과 견적 금액은 원 단위를 유지합니다. 재무 부채비율은 부채를 자본으로 나눈 뒤 100을 곱하며 자본이 0이거나 값이 없으면 정보 없음으로 표시합니다. `null`을 0으로 바꾸지 않습니다. 원본 JSON도 근거 상세에서 확인할 수 있습니다.

## 화면별 현재 상태

| 경로 | 현재 동작 |
| --- | --- |
| `/chat/:conversationId?` | 실제 로그인 계정의 직접 질문과 개인 대화 이력 |
| `/evidence/:conversationId/:responseId/:evidenceId` | 저장된 답변의 기업 근거와 법령 원문 표시 |
| `/login` `/signup` `/signup/pending` | 실제 인증 API와 가입 승인 상태 확인 |
| `/overview` | 예시 RFQ 목록과 AI 대화 진입. RFQ 목록 API는 아직 연결하지 않음 |
| `/suppliers` | 별도 조회 화면 연결 준비 안내. 검색 요청과 첫 기업 자동 선택을 실행하지 않음 |
| `/review` | 예시 협상안과 법규 검토 결과. 재검사 API는 미연결 |
| `/admin` 및 하위 경로 | 서버에서 확인한 ADMIN 계정만 진입. 회원 승인과 권한 관리 및 데이터 관리 화면은 연결 준비 안내 |

관리자 백엔드 API가 있어도 현재 관리자 화면에서 승인이나 등록을 실행하지 않습니다. 기존 시안의 예시 회원과 등록 요청을 실제 관리 결과로 표시하지 않습니다. 후속 UI 연결 시 [회원 계약](../docs/contracts/membership.md)과 [법령 관리 계약](../docs/contracts/admin-laws.md)을 확인해야 합니다.

협력사 조회용 기존 `/api/v1/business/catalog`와 `/api/v1/suppliers` 코드는 남아 있지만 현재 기본 서버와 연결된 기능으로 제공하지 않습니다. 기업 정보는 AI 대화의 business MCP 도구 조회로 확인합니다.

## 로컬 실행

Node.js 22.12 이상이 필요합니다. 먼저 [백엔드 실행 안내](../backend/README.md)와 [개발 시작 가이드](../docs/GETTING_STARTED.md)를 따라 PostgreSQL 애플리케이션 DB와 Spring 및 Python Agent를 준비합니다. stub 모드에서도 회원과 세션 및 대화 이력을 저장할 애플리케이션 DB는 필요합니다.

로컬 HTTP에서는 Spring에 `SESSION_COOKIE_SECURE=false`를 설정합니다. 운영 HTTPS에서는 기본값인 `true`를 유지합니다. 실제 모델 실행에는 [Agent 설정](../agent/README.md)에 맞는 모델과 business MCP 및 law MCP 연결이 필요합니다.

저장소 루트에서 실행합니다.

```bash
cd frontend
npm ci
NEGOPILOT_BACKEND_URL=http://127.0.0.1:8080 npm run dev
```

기본 화면 주소는 `http://127.0.0.1:5173`입니다. 포트가 이미 사용 중이면 Vite가 다른 포트를 선택할 수 있습니다. 고정 포트가 필요하면 아래처럼 실행합니다.

```bash
NEGOPILOT_BACKEND_URL=http://127.0.0.1:8082 VITE_API_TIMEOUT_MS=180000 \
  npm run dev -- --port 5176 --strictPort
```

| 설정 | 기본값 | 용도 |
| --- | --- | --- |
| `NEGOPILOT_BACKEND_URL` | `http://127.0.0.1:8080` | Vite 개발 프록시의 Spring 주소 |
| `VITE_API_TIMEOUT_MS` | `40000` | 일반 API 요청 제한. 밀리초 정수로 1000 이상 설정 |

질문 생성 요청은 `max(330000, VITE_API_TIMEOUT_MS)`를 기다립니다. Python 300초와 Spring 310초 설정을 사용할 때 브라우저가 먼저 중단하지 않도록 한 값입니다. 일반 이력 조회는 모델 실행이 끝날 때까지 DB 트랜잭션을 유지하지 않으므로 기본 40초 제한을 사용합니다. 환경에 맞게 Python과 Spring 및 브라우저의 제한을 함께 조정합니다.

내부 API 키와 DB 비밀번호 및 모델 키는 `VITE_` 환경변수에 넣지 않습니다. 화면에는 비밀 설정이 필요하지 않습니다.

```bash
npm run check:api   # API 경계와 근거 데이터 변환 회귀 검사
npm run typecheck  # Vue와 TypeScript 타입 검사
npm run build      # 타입 검사 후 dist/ 생성
```

배포 시 `dist/`를 제공하고 `/api`를 Spring으로 전달하는 동일 출처 프록시를 구성합니다. `/chat/...` 같은 직접 URL 접근은 SPA의 `index.html`로 연결해야 합니다. `NEGOPILOT_BACKEND_URL`은 개발 프록시 설정이며 빌드 결과에 운영 프록시를 만들어 주지 않습니다.

## 기능 확인 순서

1. 회원가입 후 로그인해 승인 대기 상태를 확인합니다. 관리자 API로 승인한 뒤 승인 상태 확인 버튼을 누릅니다.
2. `/chat`에서 기업을 선택하지 않고 질문합니다. live 환경에서는 실제 데이터에 있는 기업명으로 상세 정보를 질문합니다. stub 환경에서는 [직접 질문 계약](../docs/contracts/direct-chat.md)의 테스트 예시를 사용합니다.
3. 같은 대화에서 후속 질문을 보내고 답변과 조회 근거를 확인합니다. 기본 정보와 인증 및 품질의 출처가 각각 표시되는지 확인합니다.
4. 대화 목록에서 다른 대화를 열고 다시 돌아옵니다. 새로고침 후에도 이력이 남는지 확인합니다. 제목 변경과 삭제를 확인합니다.
5. 답변의 인용 링크를 열어 원본 근거와 납기율 및 원 단위 금액을 확인합니다. 서버 재시작 후 같은 계정으로 이력을 다시 열어 봅니다.
6. 다른 회원으로 로그인하면 앞 계정의 대화 목록과 상세에 접근할 수 없어야 합니다. 실패한 생성 요청은 성공 답변으로 저장되지 않고 질문을 재시도할 수 있어야 합니다.

`check:api`는 서버를 실행하지 않는 회귀 검사입니다. DB 이력 계약과 전체 응답 보존 및 FAILED 처리와 CSRF와 세션 쿠키 및 타임아웃과 요청 취소를 검사합니다. flat MCP 필드와 백분율 및 원 단위 변환과 필드별 출처도 검사합니다. 실제 모델과 DB 및 브라우저 연동 확인은 위 순서로 별도 수행합니다.
