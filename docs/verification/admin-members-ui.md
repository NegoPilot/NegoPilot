# 관리자 회원 조회와 가입 승인 화면 검증

검증일은 2026-10-21 KST다. 기존 `feat/32-spring-http-backend` 브랜치에서 프런트를 수정했다. 최신 `main`의 `b15745b`를 병합했다. Spring의 기존 `/api/v1/admin/members` 계약과 DB를 유지한다.

## 연결 범위

- `/admin`에서 전체 회원과 승인 대기 및 활성 회원 수를 서버에서 조회한다.
- `/admin/members`에서 회원 검색과 역할 및 상태 필터와 서버 페이지 조회를 제공한다.
- `/admin/approvals`에서 `PENDING` 회원만 조회한다.
- 두 회원 화면의 가입 승인과 반려는 UUID로 기존 상태 변경 API를 호출한다. 승인 후 `USER/ACTIVE`가 된다.
- 성공 응답 후 목록을 다시 조회한다. 중복 요청을 막고 인증 및 권한 오류가 나면 화면의 회원 정보를 비운다.
- 아직 연결하지 않은 접근 이력과 데이터 관리 화면은 안내 화면을 유지한다. 관리자 승격이나 회원 정지는 이번 UI 범위에 넣지 않았다.

## 실제 공유 환경 검증

외부에서 접속하는 공유 HTTPS 환경에서 검증했다. 독립 Docker 프로젝트 `negopilot-shared`의 프런트 컨테이너만 다시 빌드했다. 백엔드와 DB 및 Agent와 터널은 재시작하지 않았다.

실제 팀원 계정은 변경하지 않았다. 별도로 생성한 검증 계정 두 개로 다음을 확인했다.

| 항목 | 확인 결과 |
| --- | --- |
| 관리자 로그인 | 공개 HTTPS 화면에서 기존 공유 관리자 계정으로 로그인 |
| 회원 조회 | 실제 DB 회원 5명 표시. 예시 회원 데이터를 사용하지 않음 |
| 가입 승인 | `승인화면 검증회원` 버튼 실행 후 성공 안내와 `활성` 상태 표시 |
| 서버 저장 | 별도 관리자 세션의 회원 상세 조회로 `USER/ACTIVE` 확인 |
| 새로고침 | 페이지 새로고침 후에도 `활성` 상태 유지 |
| 승인 대기 | 승인 완료 회원이 대기 목록에서 제외됨 |
| 가입 반려 | `반려화면 검증회원`의 확인창을 수락한 뒤 대기 목록이 0건으로 변경 |
| 반려 저장 | 별도 관리자 세션에서 `USER/REJECTED` 확인 |
| 회원 검색 | 이름 `승인화면` 검색 시 해당 회원 한 명 표시 |
| 관리 현황 | 처리 후 전체 5명과 활성 3명 및 대기 0명으로 표시 |
| 승인 회원 인증 | API 로그인 성공 후 `ACTIVE` 반환 |
| 승인 회원 화면 | 브라우저에서 해당 회원으로 로그인해 AI 대화 화면 진입 |
| 일반 회원 권한 | 일반 회원의 관리자 회원 조회 API는 HTTP 403 |
| 반려 회원 인증 | 반려 회원 로그인은 HTTP 401 |

API 경계 회귀 검사와 TypeScript 검사 및 Docker 프런트 빌드가 통과했다. 검사에는 CSRF와 세션 쿠키와 상태 열거값 및 응답의 대상 UUID 일치가 포함된다.

검증 후 승인용 계정은 `DISABLED`로 정리했다. 반려용 계정은 `REJECTED`로 남겼다. 위 표의 회원 수와 상태는 정리 전 검증 시점이다. 실제 팀원 계정은 처리하지 않았다.

스크린샷은 작업 폴더의 `artifacts/negopilot-admin-approval.png`에 보관한다. 비밀번호와 API 키는 검증 문서나 저장소에 넣지 않는다.

## 최신 프런트 통합

최신 `main`의 오른쪽 AI 대화 패널과 홈 및 협력사 화면을 그대로 유지했다. 관리자 레이아웃과 회원 화면 변경 파일은 최신 프런트 변경 파일과 겹치지 않았다. 병합 후 다음 검사를 통과했다.

```sh
cd frontend
npm run check:api
npm run build
```

Node 22 기반 Docker 프런트 빌드에서도 API 검사와 TypeScript 검사 및 Vite 빌드를 실행한다. 통합한 프런트만 공유 서버에 다시 반영했으며 기존 백엔드와 DB 및 Agent와 터널을 유지했다.

병합 후 브라우저를 새로고침해 관리자 세션과 회원 5명의 조회를 확인했다. `승인화면` 검색은 해당 검증 회원 한 명을 반환했다. 가입 승인 화면은 대기 0건을 표시했다. 관리 현황은 전체 5명과 활성 2명 및 대기 0명을 표시했다. 업무 화면으로 이동하면 최신 홈이 열렸고 관리자 진입 링크도 유지됐다. 이번 재검증에서는 계정 상태를 추가로 변경하거나 모델 요청을 보내지 않았다.

이 PR은 관리자 현황과 회원 조회 및 가입 승인 화면의 실제 API 연결에 한정한다. 공유 서버 설정과 실행 스크립트 및 비밀 설정은 포함하지 않는다. 새로운 백엔드 API나 DB 변경은 없다. 위 승인과 반려 검증은 최신 프런트 병합 전에 완료한 기록이다.
