# 협력사 조회 개선 검증

2026-10-23에 이슈 #245의 구현을 검증했다. 최신 main `a3a44ad`를 기존 작업 브랜치에 반영했다. 기존 로컬 서버와 공유 서버의 프로세스 및 회원 DB는 변경하지 않았다.

## 실행 환경

- 별도 Compose 프로젝트: `negopilot-issue245`
- 검증 화면: `http://127.0.0.1:5185/suppliers`
- Vue → Spring → Python → business-mcp → 별도 PostgreSQL
- 협력사 조회: `schema_version=0.4`와 `mode=live`
- 채팅: Compose 테스트 설정의 stub. 이번 검증은 실제 모델 답변 검증이 아니다.
- 데이터: 저장소의 seed 150곳. DB 호출은 실제 호출이며 자료 출처는 DART와 MOCK을 구분한다. 생산능력과 품질 및 계약과 견적은 가상 자료다.

테스트 환경은 저장소의 `compose.yaml`과 `compose.test.yaml`을 함께 사용한다. 비공개 공유 서버 설정을 읽지 않도록 별도 env 파일을 지정했다. 해당 파일에는 테스트 포트와 dry_run 설정만 넣었으며 외부 모델 키는 넣지 않았다.

```sh
docker compose --env-file /tmp/negopilot-issue245.env -p negopilot-issue245 \
  -f compose.yaml -f compose.test.yaml up -d --build --wait

python3 scripts/integration/supplier_directory_smoke.py \
  --base-url http://127.0.0.1:5185 \
  --report /tmp/negopilot-issue245-directory-report.json

python3 scripts/integration/compose_smoke.py \
  --base-url http://127.0.0.1:5185 \
  --state /tmp/negopilot-issue245-smoke-state.json
```

위 env 파일의 내용은 다음과 같다. 로그인에는 별도 테스트 DB의 기본 USER 계정을 사용한다. 기존 사용자 DB의 계정이나 비밀번호를 변경하지 않는다.

## 브라우저 검증

실제 화면에서 입력과 버튼 클릭 및 정렬 선택으로 검증했다.

- 첫 진입에서 전체 150곳과 8페이지를 확인했다. 8페이지로 이동하면 10곳을 표시한다.
- 이름 `정밀` 검색에서 27곳을 확인했다. ID `sup-0001` 검색에서 `(주)서연이화` 한 곳을 확인했다.
- 소재만 AL6061로 검색한 뒤 2페이지로 이동했다. 소재 조건을 유지하며 11곳을 표시했다.
- 2페이지에서 내림차순으로 바꾸면 첫 페이지로 돌아간다.
- 불량률 정렬을 선택하면 품질 비교 열을 표시한다. 내림차순에서 954 ppm과 842 ppm 및 828 ppm 순서를 확인했다.
- 페이지 크기를 50으로 바꾸면 필터와 정렬을 유지하며 31곳을 한 페이지에 표시했다.
- 공정 단독과 공정 및 소재 조합을 각각 입력해 40곳과 31곳을 확인했다.
- 초기화하면 필터를 해제한 전체 목록 첫 페이지로 돌아간다.
- 상세에서 DB의 설립연도와 기본정보 및 영역별 출처와 계약의 지급기한 및 원재료 비중과 자동갱신을 확인했다.
- ID `SUP-0043`의 누리폴리머 상세에서 전체 견적 13건을 확인했다. 사출과 ABS를 직접 입력해 3건으로 좁힌 뒤 단가 내림차순의 960원과 940원 및 940원을 확인했다.
- 서버 재빌드 후에도 로그인 세션이 유지됐으며 검색 URL을 새로고침해 같은 기업을 다시 조회했다.

## 자동 검사

- 최신 main 병합 후 Python Agent 전체 테스트 1168개 통과
- business-mcp의 PostgreSQL 및 오프라인 테스트 228개 통과
- Spring 전체 테스트 771개 통과. 이 중 협력사 테스트 125개가 통과했다. 1899년 설립 기업과 필수 견적 출처의 목록 및 상세 응답을 포함한다.
- 프런트 `check:api`와 `typecheck` 및 `build` 통과
- 실제 Vue 컴포넌트 로직을 사용하는 프런트 검사에서 기본 조회와 선택 필터 및 URL 복원과 페이지 전환 및 정렬 변경 및 목록의 개별 상세 호출 제거를 확인
- 현재 생산능력에서 제거된 과거 견적의 공정과 소재 직접 입력 및 단가 정렬과 최대 생산능력의 동률 조합 표시에 대한 회귀 검사 통과
- 통합 테스트 도우미 테스트 49개 통과

초기 GitHub CI에서는 기존 Agent 취소 테스트의 50ms 제한이 목표 Generation 단계에 진입하기 전에 만료됐다. 테스트가 목표 transport에 진입한 뒤 실제 asyncio 타임아웃을 만료시키도록 수정했다. 실제 취소 전달과 504 응답 및 재시도 없음과 클라이언트 종료 검증을 유지한다. 운영 타임아웃 코드는 바꾸지 않았다.

최신 main이 추가한 관리자 견적 등록과 V3의 출처 컬럼도 반영했다. 목록과 상세 및 전체 이력의 개별 견적에 MOCK 또는 MANUAL 출처를 표시한다. DB 회귀 검사는 최근 5건 밖의 과거 MOCK과 새 MANUAL이 함께 있을 때 전체 운영 출처를 MIXED로 유지하는지 확인한다. 실제 Vue 상세 템플릿 검사에서도 두 출처를 별도 표시한다. 최종 브라우저에서는 누리폴리머의 seed 견적 13건 각각에 MOCK 가상 데이터 표시를 확인했다.

## 조회 계획과 데이터 범위

별도 seed DB에서 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`으로 실제 목록 SQL을 확인했다. 전체 목록의 실행 시간은 13.703ms였다. CNC가공과 AL6061 조건은 3.422ms였다. 이름 정밀과 불량률 내림차순은 5.181ms였다. 각각 한 번의 관측값이며 운영 성능을 보장하는 측정은 아니다.

기존 인덱스의 Bitmap Index Scan과 Index Scan이 사용되었다. 작은 테이블에는 Seq Scan도 사용되었다. count와 페이지는 하나의 SQL에서 같은 스냅샷으로 계산한다. 결과 전체를 Python이나 브라우저로 전송하지 않는다. 현재 150곳의 자료에서 추가 인덱스는 도입하지 않았다. 자료가 늘어나면 이름 부분 검색과 대표 견적 계산의 실행 계획을 다시 확인해야 한다.

이번 이슈에서 새 DB 컬럼과 마이그레이션은 추가하지 않았다. 최신 main에 있는 `V3__quote_source.sql`을 사용하며 Spring 없이 DB를 준비하는 기존 `migrate_management.py`도 V3를 적용하도록 갱신했다. 원천 기준일과 건별 발주 및 납품 실적과 견적별 수량 및 유효기간은 현재 DB에 없다. 수집 가능한 원천이 정해지지 않았으므로 가상 값으로 채우지 않았다. 기존 `updated_at`은 데이터 관리 시각으로 표시한다. 담당자 정보는 mail-mcp의 별도 권한 범위로 유지한다.

조회 API는 v0.4로 함께 전환해야 한다. 구형 프런트와 새 조회 응답의 혼용을 보장하지 않는다. 챗봇의 v0.3 계약과 top-N 도구 및 관리자 API는 유지한다.
