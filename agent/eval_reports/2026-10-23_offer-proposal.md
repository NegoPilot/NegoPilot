# 협상안 생성 평가 (2026-10-23, #231)

`scripts/eval_offer_proposal.py`를 로컬 seed DB(협력사 150곳)의 business-mcp에 붙여 돌렸다. 모델을 부르지 않으므로 비용이 없고, 같은 DB면 결과가 매번 같다.

## 사례

`eval_data/offer_proposal_cases.json` 16개, 기준일 2026-10-23.
- RFQ 6개 × `rank_suppliers` 상위 2곳 = 12개 (조건 입력 없음, 전부 데이터로 채움)
- 경계·요청 조건 4개: 요청 지급 90일·연동 없음(원재료 42%), 직전 견적이 목표보다 17% 높음, 시장가 기준 요청 + 거래 기간 60일, 요청 목표 단가·최대 수용가·비고

## 해석과 한계

- **위반 수정 루프는 실제 데이터에서 한 번도 돌지 않았다** (고침 0건). 후보를 만들 때 이미 지급 60일 이내와 연동 규칙을 적용하고, 구매자 규모를 넣지 않으면 `check_offer`가 연동 누락을 위반이 아닌 경고로 낮추기 때문이다. 루프는 단위 테스트(가짜 `check_offer`)로만 검증했다.
- **신규 협력사 3곳(o01, o02, o11)은 원재료 비중을 몰라 연동 약정 없이 나왔다.** 기존 계약이 없어 비중이 비어 있고, `check_offer`도 `RAW_MATERIAL_RATIO_UNKNOWN` 경고만 낸다. 비중을 요청 조건으로 받으면 해결되지만 화면에서 꼭 묻게 할지 정해야 한다.
- 모든 사례에 `BUYER_SIZE_UNKNOWN`, `SME_STATUS_UNKNOWN` 경고가 붙는다. 기업 규모 입력이 없어서다. 또 #228 때문에 기준일이 2026-10-24 이후면 규모를 넣어도 판정이 보류된다.
- 지급 조건 양보안은 목표가 중심안과 경고 수·목표 단가 차이가 같을 때 순서상 밀려서 `intent=payment`일 때만 고른다.
- 단가 하한(시장가 90%, 직전 견적 5% 인하)은 `check_offer`의 내부 경고 기준이다. 법이 정한 수치가 아니다.
- 사례가 실제 DB에서 뽑은 16개뿐이고, 정답 협상안을 사람이 정한 평가가 아니다. 규칙대로 계산되는지와 위반 소지가 없는지만 본다. 협상안이 "좋은지"는 담당자 검토가 필요하다.
