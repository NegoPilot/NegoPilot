## 해석과 제한

- **gv13이 연결 효과를 그대로 보여 준다.** 연결 전에는 분해가 `energy_ratio: 0.15`를 뽑아도 Router가 check_offer에 넘기지 않아, 서버가 `ENERGY_RATIO_UNKNOWN`(info)만 내고 판정이 "문제 없음"이 됐다. 연결 후에는 `ENERGY_LINKAGE_TERMS_MISSING`(violation)이 나와 "위반 소지 있음"으로 답한다.
- gv14는 연결 전에도 5/6이다. 에너지 합의 경고가 나오지 않았는데도 채점이 합의 관련 포인트를 일부 담았다고 본 것이라, 연결 전 점수가 실제보다 후하다.
- **gv15는 판정은 맞지만 이유를 설명하지 못한다.** 연결 후 `as_of: 2026-07-01`이 전달되어 에너지 검사를 건너뛰지만, Generation 근거(`offer_verdict`)에 `basis`(기준일, 시행판)가 없어 "에너지 규칙 시행 전이라 검사하지 않았다"는 설명이 나오지 않는다. 채점은 "계약일은 2026년 7월 1일" 문장을 근거 없는 주장으로 표시했다(2회 모두). 후속 작업 후보: 근거에 `basis`를 넣고, 규칙 시행 전이라 건너뛴 검사를 알려 주는 항목 추가.
- 연결 후 재생성·근거 미표시 1건은 gv11(협력사 재무 상세)로, 협상안과 무관하다.
- 시간 차이는 연결 전 17.76초 요청 1건의 영향이 크다. 연결 자체가 시간을 줄였다고 보지 않는다.
- 근거 없는 주장 수는 LLM 채점 경고이며 확정 오류 수가 아니다. 같은 생성·채점 모델과 작은 질문 집합의 2회 반복 결과라 일반화하지 않는다.
- 오류 코드(`RFQ_NOT_FOUND` 등) 안내는 Generation 검증 세트에 넣지 않았다. 검증 세트는 모든 도구 호출이 성공한 경우만 담고, `ToolCall.error_code`는 저장되지 않는다. 오류 코드는 agent·shared 단위 테스트가 다룬다.
