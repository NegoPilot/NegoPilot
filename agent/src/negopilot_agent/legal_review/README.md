# 상황별 검토 초안

자연어 상황에서 지원 쟁점을 식별하고, 필요한 사실을 질문하며, 쟁점별 실제 법령을 조회해 검토 목록을 제시한다. main `77e2c6e` 위에서 테스트한 별도 CLI다. 기존 `/chat`·`/review`에 자동 적용하지 않았다.

## 실행

law MCP를 띄우고 `agent/.env`에 기존 방식으로 모델 키와 `LAW_MCP_URL`을 설정한다. 모델 호출 비용이 발생한다. 저장소 루트가 아니라 `agent/`에서 실행한다.

```bash
uv run python scripts/review_situation.py --as-of 2026-10-23 --json '원자재 가격이 올라 협력사가 단가 조정을 요청했습니다. 연동 약정은 없습니다.'
```

계획 단계는 gpt-4.1-mini를 기본으로 사용한다. 기본 출력은 코드로 조립하므로 별도 답변 생성 모델은 호출하지 않는다. Python API는 `SituationReviewer.review(query, as_of, history=None)`다. 기준일을 명시적으로 받으며 모든 조문 조회에 같은 날짜를 전달한다.

## 처리

1. 모델이 `price_stage`, 지원 쟁점, 원문 인용, 필요한 사실 질문, 미지원 요청을 구조화한다. 인용이 실제 원문에 없으면 한 번 재시도하고, 계속 잘못되면 검토를 실행하지 않는다. 원문 인용 검증은 의미 분류의 정확성을 보장하지 않는다.
2. 인하 대상 시점이 불명확하면 결정·감액을 함께 후보로 둔다. 모델이 같은 뜻으로 물은 시점 질문·적용 대상 질문은 정해 둔 질문과 겹치지 않게 하나만 남긴다. 원가 조정 협의에는 연동 검토를 보충한다. 이는 적용 확정이 아니라 누락 방지용 검토 경로다.
3. 검증한 시작 조문을 기존 Router의 `law_article`로 조회한다. 신규 대금 결정→하도급법 제4조, 기존 대금 감액→제11조, 원가 조정→제16조의2, 연동→제3조 및 정의 제2조. 모델이 임의로 조문 번호를 생성하지 않는다. 매핑은 main 법령 데이터의 제목을 대조했다.
4. 기존 근거 구성기를 재사용해 실제 조회된 조문의 인용과 본문을 보관한다. 쟁점·인용·질문 목록은 코드로 조립한다. 쟁점마다 먼저 읽을 항(`KEY_PARAGRAPHS`: 제4조①, 제11조①③, 제16조의2①⑩, 제3조④, 정의 제2조⑯⑱)을 법령 원문 그대로 400자까지 발췌해 보여 준다. 항 번호는 시행 2026-10-02 판본에서 확인했고, 테스트가 현재 법령 데이터에 그 항이 있는지 검사한다. 발췌는 해석이 아니며 단서·다른 항은 전체 근거에서 확인해야 한다. 자유로운 법률 해석 답변은 기본 경로에서 생성하지 않는다. 조회 실패·미지원 범위를 안내한다.

## 범위와 한계

네 가지 쟁점에서 시작하는 제한된 초안이다. 모든 법률 쟁점을 스스로 발견하는 범용 에이전트가 아니며, 실제 거래의 적용 대상·기업 규모를 자동 확정하지 않는다. 이 단계는 business MCP를 호출하지 않는다. 도형님의 기업 규모/협상안 검사와 연결할 입력 계약은 별도 합의가 필요하다.

시행령에 위임된 숫자·세부 요건과 심사지침·참조 조문의 재귀 조회는 아직 포함하지 않았다. 따라서 시작 조문이 조회됐다고 모든 필수 조문이 확보된 것은 아니다. 근거 본문은 기존 생성기의 길이 제한·항 선택을 따른다. 향후 조문 개정 시 시작 조문 매핑도 검토해야 한다.

추가 질문은 이력을 넘겨 재검토할 수 있으나 현재 CLI는 한 번의 실행이다. 기업 증빙·협의 사실의 진위를 검증하지 않는다. 초기 검증에서 자유로운 답변 생성은 약정 누락과 법정 예외를 혼동하는 오류가 지침 추가 후에도 재현돼 기본 경로에서 제외했다. 현재 결과는 쟁점과 시작 조문 및 확인 질문이며, 쟁점별 적용 판단은 아직 제공하지 않는다. 독립 출처의 정답으로 법률 정확도를 측정하기 전에는 실제 의사결정용으로 배포하지 않는다.

합성 개발 사례의 쟁점 선택 통과율은 독립 평가 성능이 아니다. 초기 실패 사례를 보고 수정했으므로 동일 사례의 재실행은 회귀 확인으로만 해석한다. 기존 #219 평가 실행·집계를 대체하는 평가 도구는 만들지 않았다.
